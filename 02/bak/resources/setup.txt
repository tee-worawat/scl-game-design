GAME DESIGNER · desktop Python starter
Use Python 3.12 and pygame-ce 2.5.8 (the development test environment).
Teacher: install and test on every classroom OS before class. Other Python versions are unverified.

Extract the WHOLE ZIP. Keep starter.py, studio.py, images/ and fonts/ together.
Open a terminal in the extracted folder.
Windows: py -3.12 -m venv .venv
macOS/Linux: python3.12 -m venv .venv
Windows install: .venv\Scripts\python -m pip install -r requirements.txt
macOS/Linux install: .venv/bin/python -m pip install -r requirements.txt
Windows run: .venv\Scripts\python starter.py
macOS/Linux run: .venv/bin/python starter.py

Initial installation needs internet and permission to install packages. Afterwards games run locally without accounts or internet. A Chromebook/browser-only device is not an assumed supported setup.
Keep a tested copy of each lesson for catch-up. Do not name your file pygame.py.

Controls: arrows move from lesson 2; R resets from lesson 4; Esc or close quits.
Hold H to show the player's 48×48 hitbox. Artwork is scaled at runtime; source PNGs are unchanged.
Lesson 1 is a static scene. Lessons 1–3 restart by closing and running again.
Each lesson is a separate concept checkpoint, not a promise that every earlier mechanic is carried forward.
Lessons 6–10 omit the countdown; lesson 8 onward omit the patrol to isolate data and design.

studio.py is teacher-provided infrastructure. It owns window/events, dt, graphics, font loading and a simple touching helper. Read it when ready; it is not learner-authored evidence. Students edit starter.py. Pre-lesson 00 introduces simple classes and independent objects. The graphical lessons use functions; inheritance, a physics engine and Unity syntax are not required.
Game UI and code identifiers use English; teacher guidance is bilingual. Accept Thai explanations.
