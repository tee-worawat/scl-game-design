02 · ขยับผู้เล่น: จากไฟล์เดียวสู่ตัวช่วยใช้ซ้ำ

ติดตั้งก่อนคาบ รัน 01_loop.py, 02_functions.py, main.py และ modular/main.py ครู ตรวจเส้นทาง ภาพ และความเร็ว 180 เดิม

แจกเฉพาะ student-project.zip main.py ต้องเปิดฉากนิ่ง ส่วน stub แยกโมดูลต้องให้ผู้เรียนย้าย helper ก่อนรัน

พิมพ์ใบงานและแผนจุดตรวจ ซ่อนโค้ดครบและเฉลยช่วงคาดการณ์ ใช้หน้าต่าง Python จริงช่วงทดลอง

เตรียมบัตร x/y ของผู้เล่นสองตัว สลับผู้พิมพ์/ผู้นำทาง บันทึกจุดตรวจที่รันได้ก่อนจัดโครงใหม่

ก่อนคาบเชื่อมรัน 04_sprites.py ครู แจกไฟล์ผู้เรียนชื่อเดียวกันที่เคลื่อนได้แล้วแต่มี TODO sprite สองจุด ดู images/robot-directions.png เป็นแผ่นรวม โค้ดโหลด PNG แยกสี่ไฟล์


เล่น · เปิดไฟล์เดียว (8 min)

สมมติว่ารู้ตัวแปร if และเคยเห็น import/def เล็กน้อย แสดง import pygame เทียบกับการเรียกฟังก์ชัน ไล่ x=160 แล้ว x+=18 ไม่สมมติว่าจำคลาสจากบท 00 ได้

PROMPT: บรรทัดใดทำให้ใช้ pygame ได้? เขียน def แล้วเรียกฟังก์ชันหรือยัง?

ANSWER: import ทำให้ใช้โมดูลได้ def นิยามฟังก์ชัน main() เรียกใช้งาน เงื่อนไขเปิดโปรแกรมเป็นโครงช่วย ไม่ใช่จุดประเมิน

EVIDENCE: แต่ละคนแยก import การนิยาม และการเรียกได้ด้วยการชี้หรือภาษาไทย


คาดการณ์ · สองก้าวเล็ก (7 min)

แสดงเฉพาะโค้ดเคลื่อนที่จาก 01_loop.py ครู ยังไม่รัน ใช้บัตร dt=0.05 ถามทั้งคู่ก่อนเฉลย

PROMPT: ใน 01_loop.py เริ่ม x=160 speed=180 กดขวา dt=0.05 หลังอัปเดตหนึ่งและสองครั้ง x เท่าไร? ปล่อยปุ่มแล้วเป็นอย่างไร?

ANSWER: 169 แล้ว 178 เพราะ dx=1 จึงบวกครั้งละ 9 ปล่อยปุ่ม dx=0 ตำแหน่งคงเดิม tick คืนมิลลิวินาที หาร 1000 เป็นวินาที จำกัด 0.05 เพื่อไม่กระโดดไกลหลังหยุดนาน

EVIDENCE: คาด 169,178 และอธิบายว่าปล่อยปุ่ม dx=0


ทดลอง · ดูลูปทำงาน (5 min)

รัน 01_loop.py ครูโดยไม่แก้ กด/ปล่อยลูกศร ปิดแล้วเริ่มใหม่ เทียบการเคลื่อนและหยุดกับกระดาษ เวลาเล่นจริงอาจต่างกัน

PROMPT: ปล่อยปุ่มแล้วอะไรยังวาดอยู่?

ANSWER: ลูปยังทำงาน dx/dy เป็นศูนย์ ตำแหน่งคงเดิมแต่เฟรมวาดใหม่

EVIDENCE: แยกผู้เล่นหยุดกับลูปหยุด


สำรวจ · ตั้งชื่องานวาด (12 min)

เติม TODO เคลื่อนที่สองบรรทัดใน main.py เริ่มแนวนอน บันทึก my_loop.py เทียบ 02_functions.py ย้ายพื้นหลังไป draw_scene และโหลดภาพไป load_sprite อธิบายพารามิเตอร์และ return ด้วยพาธภาพหนึ่งภาพ ยังไม่แนะนำ Player

PROMPT: helper ใดทำครั้งเดียว ใดทำทุกเฟรม? ทำไมต้องล้างจอก่อน?

ANSWER: โหลดแต่ละภาพครั้งเดียวหลัง set_mode draw_scene ล้างและวาดทุกเฟรม return ส่งภาพย่อกลับผู้เรียก วาดผู้เล่นทีหลังเพื่อไม่ถูกลบ

EVIDENCE: ชี้ load_sprite ก่อนลูป และ draw_scene ในลูป ฉากยังวาดครบ


สำรวจ · ให้ผู้เล่นมีสถานะของตน (18 min)

บันทึก my_functions.py เปิด 03_player.py ทีละส่วน class เป็นแบบ Player(...) สร้างออบเจ็กต์ __init__ เก็บข้อมูล self คือออบเจ็กต์ที่รับคำสั่ง move/draw เป็นเมธอด ให้ constructor/draw เป็นโครง ผู้เรียนปรับการเคลื่อนที่เป็น self สลับบทบาทหลัง 9 นาที แสดง object_probe.py หลังคาดการณ์

PROMPT: nova.move(1,0,0.05) เปลี่ยน x ของใคร? ถ้า pip เริ่ม 500 จะเกิดอะไรกับ pip?

ANSWER: nova.x เป็น 169 pip.x คง 500 ใช้คลาสเดียวกันแต่แต่ละตัวมี x/y/speed ของตน เมธอดคือฟังก์ชันของออบเจ็กต์

EVIDENCE: เคลื่อนที่ได้และแต่ละคนอธิบาย self กับ pip.x ที่ไม่เปลี่ยน


ปรับแก้ · จูนการเคลื่อนที่ (10 min)

ใช้ Player ไฟล์เดียวที่ทำเสร็จ คงจุดเริ่มและเป้าหมายเมื่อทดสอบความเร็ว แสดง teacher_example.py หลังลองแก้เอง

PROMPT: ในเวอร์ชัน Player เปลี่ยน self.speed จาก 180 เป็น 240 คาดว่าจะไป 12 พิกเซลต่อ dt=0.05 ทดลองเส้นทางเดิมสู่แท่นและอธิบายผลต่อความแม่นยำ

ANSWER: 240*0.05=12 ไปเร็วอาจหยุดแม่นยากขึ้น รับความชอบต่างกันหากมีผลสังเกต

EVIDENCE: อธิบายผลต่อความแม่นจากการทดลอง ไม่ใช่เปลี่ยนสีอย่างเดียว


สำรวจ · นำเข้า helper ของเรา (10 min)

นำแยกไฟล์: บันทึก my_player.py นำโค้ดที่เสร็จไป modular/main.py ย้าย load_sprite/draw_scene ไป modular/scene.py พร้อม import pygame ลบนิยามเดิมแล้วใช้ from scene import load_sprite, draw_scene คงหน้าต่างและลูปใน main.py พาธภาพขึ้นหนึ่งโฟลเดอร์เพราะอยู่ใน modular/ ทดสอบจุดเริ่ม/ความเร็ว/เป้าหมายเดิม

PROMPT: import draw_scene แล้ววาดอะไรหรือยัง? การเรียกใดต้องอยู่ในลูป?

ANSWER: import ทำให้ใช้ฟังก์ชันได้ ยังต้องเรียก draw_scene(screen,pad,pad_position) ในลูป scene.py นิยาม helper โดยไม่เปิดหน้าต่าง ไม่ต้อง import วนกลับ

EVIDENCE: ชี้ไฟล์นิยาม บรรทัด import และการเรียกได้ แยกแล้วเคลื่อนเหมือนเดิม


สร้าง · ออกแบบฉากจอด (13 min)

ใช้ไฟล์เดียวหรือแยกไฟล์ที่รันได้ วางแผน 3 นาที สร้าง 6 สลับทดสอบ 3 บันทึก 1 ต้องมีการตัดสินใจเคลื่อนที่และสัญญาณเส้นทางพื้นหลัง ไม่ใช่ตกแต่งอย่างเดียว

PROMPT: เลือกจุดเริ่ม ตำแหน่งแท่น และความเร็วเพื่อออกแบบภารกิจจอดอย่างแม่นยำ ใช้ตัวช่วยฉากวาดเส้นทาง ให้คู่ลองหยุดบนแท่น แล้วใช้ผลปรับการเคลื่อนที่หนึ่งอย่าง ยังไม่มีตรวจชนหรือตรวจชนะอัตโนมัติ

ANSWER: ผลได้หลายแบบ ใช้การหยุดทับแท่นด้วยสายตา ไม่อ้างว่ามีคะแนนหรือตรวจชนอัตโนมัติ

EVIDENCE: คู่ลองเส้นทางได้และผู้สร้างอธิบายการเปลี่ยนพฤติกรรม


เติบโต · อธิบายด้วยตนเอง (7 min)

ตรวจรายคน 4 นาที บันทึกทั้งโฟลเดอร์ 2 นาที เลือกขั้นต่อไป 1 นาที ถามทั้งคู่ แยกทำเองกับมีคนชี้แนะ ไม่ถือว่ารันได้แปลว่าเข้าใจ

PROMPT: กรณีใหม่ a.x=200 a.speed=120 เรียก a.move(-1,0,0.5) a.x เท่าไร? ถ้า b.x=500 จะเปลี่ยนไหม? บอกสองบรรทัดที่ใช้ draw_scene จาก scene.py

ANSWER: a.x=140 ส่วน b.x คง 500 เพราะ self ในครั้งนี้คือ a ใช้ from scene import draw_scene แล้วเรียก draw_scene(screen,pad,pad_position) ในลูป import ทำให้ใช้ฟังก์ชันได้ การเรียกจึงวาดเฟรมนี้ การไล่เมธอดโดยตรงใช้ dt=0.5 แต่ลูปจริงจำกัด dt=0.05

EVIDENCE: ตรวจสามข้อแยกกัน: การเคลื่อนที่ เจ้าของสถานะ และใช้ helper ซ้ำ


บทเชื่อม · sprite คืออะไร? (5 min)

เริ่มคาบเชื่อม 45 นาทีหลังตรวจการเคลื่อนที่ เก็บโปรเจกต์ Player เดิม แสดง PNG สี่ทิศและโค้ดครู 04_sprites.py ก่อนรัน sprite คือภาพแทนวัตถุในเกม Player เก็บตำแหน่งและเลือกภาพ ภาพนี้เปลี่ยนทิศ ยังไม่ใช่แอนิเมชันเดิน

PROMPT: เริ่มหันลง ทำนายภาพหลัง กดขวา ปล่อย กดขึ้น การเลือกภาพทำให้ x หรือ y เปลี่ยนไหม?

ANSWER: right, right, up การเลือกภาพไม่ย้ายตำแหน่ง move เปลี่ยน x/y อีกส่วนหนึ่ง

EVIDENCE: แยกตำแหน่ง ทิศ และภาพได้ก่อนดูเกม


Run · มองจากด้านบน (5 min)

รัน 04_sprites.py ของครูโดยไม่แก้ เทียบคำทำนาย ลองสี่ทิศ ปล่อย และขึ้นพร้อมขวา ชี้ว่าไฟล์ผู้เรียนเคลื่อนได้แต่ตั้งใจค้างภาพหันลงจนเติม TODO

PROMPT: เมื่อเดินขึ้นเห็นส่วนไหนของหุ่น? เมื่อปล่อยปุ่มเกิดอะไรขึ้น?

ANSWER: ขึ้นเห็นหลังและหัวด้านบน ปล่อยแล้วหยุดแต่จำทิศเดิม ขึ้นพร้อมขวาเดินเฉียงและใช้ภาพขึ้น

EVIDENCE: จำภาพด้านหลังและทิศที่คงอยู่เมื่อหยุดได้


Investigate · ตู้ภาพของ Player (12 min)

เริ่ม dictionary หนึ่งครั้ง sprites["up"] เลือกภาพที่เก็บใต้คีย์ up อ่านสี่คู่ก่อนใช้ self.sprites[self.facing] ไล่ __init__ แล้ว if/elif ใน move และ draw โหลดภาพครั้งเดียวนอกลูป ทุกภาพใช้กรอบ 64px และจุดกึ่งกลางเดียวกัน draw เลือกภาพทุกเฟรม ยังไม่สอน inheritance หรือ pygame.sprite.Sprite

PROMPT: แอตทริบิวต์ใดจำทิศ? ทำไมไม่มี else สุดท้ายที่ตั้ง down?

ANSWER: self.facing เก็บข้อความเช่น "up" ส่วน self.sprites จับคู่คีย์กับภาพ ถ้าไม่เข้ากิ่งใดจะเก็บค่าเดิม else สุดท้ายจะทำให้หันลงเมื่อปล่อย

EVIDENCE: อธิบายว่า self.facing เป็นของ Player นี้และไม่เปลี่ยนเมื่อไม่มีอินพุต


Modify · เดินเฉียงเลือกภาพไหน? (8 min)

เมื่อ TODO หลักทำงาน ให้คู่เปลี่ยนลำดับเงื่อนไขเพื่อให้แนวนอนชนะเมื่อเดินเฉียง ทำนายก่อนทดสอบขึ้นพร้อมขวา คงโค้ด x/y เดิม สลับหน้าที่ครึ่งทาง

PROMPT: อะไรควรเปลี่ยน และอะไรควรเหมือนเดิม?

ANSWER: if/elif เลือกกิ่งแรกที่จริง แนวนอนก่อนจะแสดง right เมื่อ dx=1,dy=-1 การเคลื่อนที่ยังอัปเดตทั้งสองแกน

EVIDENCE: เคลื่อนเฉียงเหมือนเดิม แต่ใช้ภาพขวาแทนขึ้น


Make · หันให้ตรงสถานี (10 min)

ผู้เรียนเลือกจุดหยุดสองจุดพร้อมทิศที่ต้องหัน วางแผน 2 นาที เขียนและลอง 5 รับคำแนะนำ 2 บันทึก 1 ตรวจด้วยตาเท่านั้น ยังไม่เพิ่มชนหรือคะแนน

PROMPT: ออกแบบเส้นทางที่หยุดถูกที่อย่างเดียวไม่พอ หุ่นต้องหันเข้าหาสถานีด้วย

ANSWER: ยอมรับเส้นทางต่างกัน ต้องเลือกภาพถูก ไม่เด้งหันลงเมื่อปล่อย และอธิบายกติกาเดินเฉียงได้

EVIDENCE: เส้นทางที่เลือกทิศสองจุดอย่างมีเหตุผลและแก้หนึ่งอย่างหลังรับคำแนะนำ


Grow · ใครเปลี่ยนทิศ? (5 min)

ประเมินแต่ละคนแยกกันแล้วบันทึกทั้งโฟลเดอร์ ใช้กติกาแนวตั้งก่อนแบบต้นฉบับ ตรวจคำอธิบายการเคลื่อนที่กับทิศก่อนเข้า 03 ถ้ายังต้องช่วยให้ลองไล่อีกกรณี

PROMPT: a และ b เริ่มหันลง เรียกเฉพาะ a.move(-1,0,0.05) แล้ว a.move(0,0,0.05) แต่ละตัววาดภาพไหน? ถ้า a ขึ้นพร้อมซ้ายต่อ ภาพไหนชนะ?

ANSWER: a หันซ้ายขณะหยุด b ยังลง ขึ้นพร้อมซ้ายใช้ up ในเงื่อนไขแนวตั้งก่อน ใช้ภาพร่วมกันไม่ได้ทำให้ self.facing ร่วมกัน

EVIDENCE: a ซ้าย b ลง ต่อมา a ขึ้น อธิบายสถานะแยกตัวและจำทิศเมื่อหยุด
